Loading and Saving Data: The Ghost Camera

Instead of our regular lesson today, we are embarking on a chilling adventure: ghost hunting!

The Ghost Camera

Last night we went ghost hunting with a very special device: a ghost camera. Ghosts are invisible, so we could not see anything in the dark. But the camera beeps when a ghost is nearby, and every time it beeped, we snapped a picture.

By the end of the night, the camera had met so many ghosts that it got completely spooked… and broke. When we downloaded the pictures, every photo was broken, and each one in a very different way.

Luckily, the camera keeps a log. This is what it recorded:

22:13  BEEP! Ghost nearby ............. photo_1 saved
       ERROR: memory shattered. Photo saved in 9 fragments, names scrambled.
23:02  BEEP! Ghost nearby ............. photo_2 saved
       ERROR: sensor frozen. Fragments flattened, contrast lost, image inverted.
00:31  BEEP! Ghost nearby ............. photo_3 saved
       ERROR: interference on the sensor rows.
01:45  BEEP! Ghost nearby ............. photo_4 saved
       ERROR: lens cursed. Rows scrambled. 3 lenses found in the camera bag.
03:33  BEEP! BEEP! BEEP! STRONG GHOST . photo_5 saved (colour)
       NOTE: ghost surrounded by small ORANGE flames.
       ERROR: colour channels separated and shuffled. Very low light.
03:34  CAMERA FAILURE. Too many ghosts.

Who did we catch? We do not know yet: the photos will tell us.

Our mission: load the broken files, use the log to understand what happened to each photo, recover all five pictures, and find the case number to close the investigation.

Setting Up Our Toolkit

Two helper functions:

  • show(image) displays an array as an image: grayscale if it is 2D, colour if it is 3D.
  • check(photo, key) tells you whether you found the key of a photo, for instance check(1, ...), or the case number, check("case", ...).
import hashlib
import os

import matplotlib.pyplot as plt
import numpy as np


def show(image):
    """Display an image: a 2D array (grayscale, 0 = black, 1 = white) or a 3D array (colour)."""
    if image.ndim == 2:
        plt.imshow(image, cmap="gray", vmin=0, vmax=1)
    else:
        plt.imshow(np.clip(image, 0, 1))
    plt.axis("off")
    plt.show()


_KEYS = {1: 'acba8dd74b724348', 2: 'f5ca38f748a1d6ea', 3: '9ae2bdd7beedc2e7', 4: 'd4735e3a265e16ee', 5: '72440a20f54075ac', 'case': 'cc4a9135117f2dbf'}


def check(photo, key):
    """Check the key of a photo (1 to 5) or of the case ("case")."""
    digest = hashlib.sha256(str(key).strip().upper().encode()).hexdigest()[:16]
    if digest != _KEYS[photo]:
        print(f"Wrong key for photo {photo}. Keep investigating...")
    elif photo == "case":
        print("Correct case number! The ghost hunt is solved.")
    else:
        print(f"Correct key! Photo {photo} is recovered.")

These are the tools you will need. You already know most of them!

Tool What it does
os.listdir(folder) Lists the files of a folder
os.path.join(folder, name) Builds the path of a file
np.loadtxt(path) Loads a text file (.txt); add delimiter="," for .csv files
np.load(path) Loads a NumPy binary file (.npy)
np.save(path, arr) / np.savetxt(path, arr) Saves an array as .npy / as text
np.concatenate(arrays, axis=...) Joins arrays along an existing axis (also np.hstack(), np.vstack())
np.stack(arrays, axis=...) Joins arrays along a new axis
Loading directly from the internet

np.loadtxt() can also read a text file straight from a URL, without downloading it first:

url = "https://raw.githubusercontent.com/daniprec/Python-Course/main/data/ghost_photos/photo_1/fragment_A.txt"
fragment = np.loadtxt(url)

np.load() and os.listdir() only work with files on your computer (or in your Colab session). That is why we download the whole folder.

Every photo is a \(300 \times 300\) array, with values between 0 (black) and 1 (white). When a photo is split into 9 fragments, each fragment is \(100 \times 100\), and they are placed like this:

(0, 0) (0, 1) (0, 2)
(1, 0) (1, 1) (1, 2)
(2, 0) (2, 1) (2, 2)

Two things are true for every photo of our camera:

  • It has a white frame: the 4 pixels on the border are 1.
  • Just inside the white frame, it has a thin black line: those pixels are 0.

The Five Broken Photos

For each photo, the camera log tells us what happened. This is what we have, and how to fix it.

Photo 1: The Shattered Photo

Files: ghost_photos/photo_1/fragment_A.txt to fragment_I.txt. Nine text files, one \(100 \times 100\) fragment each.

What happened: the memory shattered, and the fragments were saved with random letters. The letters say nothing about the position.

How to fix it: the camera left a trace. The top-left pixel of every fragment stores its fragment number, from 1 to 9, counted row by row. Load every fragment, read that pixel, sort the fragments by it (np.argsort() is your friend), and join them: first each row of three fragments side by side, then the three rows one on top of the other.

Key: the letters of the files sorted by fragment number, for instance check(1, "ABCDEFGHI").

Photo 2: The Frozen Photo

Files: ghost_photos/photo_2/fragment_<row>_<col>.txt. Nine text files named by position… but each one has one value per line.

What happened: the ghost’s chill froze the sensor. Each fragment was flattened into a single line of values, and the photo lost almost all its contrast: every value was squeezed into a tiny range. On top of that, it was saved as a negative (black and white swapped) and mirrored along the diagonal (rows and columns swapped).

How to fix it:

  1. Give each fragment back its square shape, and join the fragments.
  2. Stretch the values back to the range \([0, 1]\). Remember that every photo has pure black (the line) and pure white (the frame): \[\text{stretched} = \frac{\text{stored} - \min}{\max - \min}\]
  3. Undo the negative, and undo the mirror.

Key: how many times did the ghost reduce the contrast? The original photo had a range of 1 (from 0 to 1); compare it with the range of the stored values.

Photo 3: The Banded Photo

Files: ghost_photos/photo_3/fragment_<row>_<col>.npy. Nine NumPy binary files, named by position.

What happened: the ghost interfered with the sensor: every row of pixels was multiplied by a different number between 0 and 1, a gain. The photo is complete, but it is covered with dark horizontal bands. \[\text{stored} = \text{photo} \times \text{gain}\]

How to fix it: the white frame tells us the gains. The first column of the original photo is all 1, so the first column of the stored photo is exactly the gain of each row. Divide each row by its gain. Careful: broadcasting must divide the rows, not the columns. Check the shape of the gains!

Key: the first row with the strongest interference (the smallest gain).

Photo 4: The Cursed Lens

Files: ghost_photos/photo_4/fragment_<row>_<col>.csv, nine fragments in CSV format (values separated by commas), and lens_1.csv, lens_2.csv, lens_3.csv, three \(300 \times 300\) matrices.

What happened: the ghost cursed the lens of the camera. The photo went through a lens matrix \(L\), which scrambled its rows: \[\text{stored} = L \cdot \text{photo}\] We found three lenses in the camera bag, but only one of them was used.

How to fix it: undo the matrix product with the inverse of the lens, \(\text{photo} = L^{-1} \cdot \text{stored}\). A matrix has an inverse only if its determinant is not 0: that is how you find the lens that was used.

Key: the number of the lens.

Photo 5: The Colour Photo

Files: ghost_photos/photo_5/channel_1.npy to channel_4.npy. Four NumPy binary files, \(300 \times 300\) each.

What happened: the strongest ghost of the night, and our only colour photo. A colour image is a 3D array with shape (height, width, 3): one layer, or channel, for red, green, and blue. The ghost separated the three channels, saved each one in its own file, and shuffled the file numbers. One of the four files is a decoy. On top of that, it was night: every value was squared, so the photo is darker than it should be.

How to fix it: find the decoy (look at the four files). Join the other three along a new axis to get a (300, 300, 3) array, and undo the square. Which file is red, which is green, and which is blue? Try the possible orders and use the clue from the camera log: this ghost was surrounded by small orange flames. Careful with blue or green flames: those belong to other spirits (will-o’-the-wisps!), not to our ghost.

Key: the numbers of the red, green, and blue files, in that order, for instance check(5, "123").

The Case Number

Each recovered photo hides one digit of the case number: the first decimal of the mean brightness of its top-right quarter (the first 150 rows and the last 150 columns). For example, a mean of 0.4371 gives the digit 4. For the colour photo, use only its red channel.

Careful: a photo that is only half fixed gives the wrong digit. You need all five photos fully recovered.

Key: the five digits, from photo 1 to photo 5, for instance check("case", "12345").

Work in groups of three or four. Recover the five photos, in any order, and use check() to confirm each key. The first group to find the case number closes the investigation!

Summary and Reflection

  • os.listdir() lists the files of a folder, and os.path.join() builds their paths.
  • np.loadtxt() loads text files (delimiter="," for CSV), and np.load() loads .npy files.
  • np.save() keeps an array exactly, with its shape and data type; np.savetxt() writes readable text, but only for 1D and 2D arrays.
  • np.concatenate(), np.hstack(), and np.vstack() join arrays along an existing axis; np.stack() creates a new one.
  • Array arithmetic, broadcasting, aggregations, and matrix operations can undo many transformations, as long as we know what happened.
